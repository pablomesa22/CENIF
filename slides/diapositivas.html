1.3 · MapReduce (3/3)

El mismo ejemplo en código

python · en un solo ordenador

bloques = [["Pass", "Pass", "Shot"],

["Carry", "Pass", "Shot"],

["Pass", "Carry", "Pass"]]

# MAP: cada bloque emite (clave, 1)

mapa = [(t, 1) for b in bloques for t in b]

# SHUFFLE: agrupar valores por clave

grupos = {}

for k, v in mapa:

grupos.setdefault(k, []).append(v)

# REDUCE: sumar los valores de cada clave

final = {k: sum(v) for k, v in grupos.items()}

# {'Pass': 5, 'Shot': 2, 'Carry': 2}

1.4 · Coste de los JOIN (1 de 3)

Un JOIN no es gratis

clientes

contratos

101 → 1

103 → 3

Para cada fila de una tabla, el motor busca su pareja en la otra. Con pocas filas es instantáneo; con millones, es trabajo.

Bucle anidado

Compara cada fila con todas las de la otra tabla. Con índice, busca directamente; sin él, el coste se multiplica.

Hash join

Construye una tabla hash con una de las dos y consulta con la otra. Rápido, pero gasta memoria.

Merge join

Ordena las dos por la clave y las recorre a la vez. Va bien si ya están ordenadas.

El coste depende de cuántas filas hay, de si hay índices y de cuántos datos intermedios se generan.

-[:COMPRO]->(p:Producto)
