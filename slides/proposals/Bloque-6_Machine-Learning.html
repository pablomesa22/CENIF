6.1 · El problema

¿Cuál es la probabilidad de gol de un tiro?

Entrada

Dónde se tira, con qué parte del cuerpo, si había presión, la jugada.

Salida

Una probabilidad entre 0 y 1: el xG.

Para qué sirve

Medir la calidad de las ocasiones, más allá de si acabaron en gol.

Es el xG (expected goals): lo que usamos en el bloque 4 para el cuadro de mando. Ahora construimos nuestro propio modelo. StatsBomb ya calcula el suyo, con más información, y lo usaremos como referencia.

6.1 · Preparar los datos

La variable objetivo

python

tiros["gol"] = (tiros["shot_outcome"] == "Goal").astype(int)

 

print(tiros["gol"].value_counts())

print(f"Porcentaje de goles: {tiros['gol'].mean() * 100:.1f}%")

Etiqueta

gol vale 1 si el tiro acabó en gol y 0 si no.

Desbalanceo

Alrededor de uno de cada diez tiros es gol: el accuracy engaña.

Lo primero es mirar cuántos goles hay. Con pocos goles, el modelo tiene pocos ejemplos positivos y hay que cuidar la evaluación. Recordar lo visto en el bloque 5 sobre accuracy y clases desiguales.

6.1 · Feature engineering

De coordenadas a geometría

python

dx = 120 - tiros["x"]

dy = tiros["y"] - 40

 

tiros["distancia"] = np.sqrt(dx**2 + dy**2)

# Ángulo bajo el que se ve la portería (8 m de ancho)

tiros["angulo"] = np.arctan2(8 * dx, dx**2 + dy**2 - 16)

Por qué

El modelo no entiende x = 108, y = 35, pero sí distancia y ángulo.

Portería

Está en x = 120, entre y = 36 e y = 44.

6.1 · Variables categóricas

One-hot encoding

python

base = tiros[["distancia", "angulo", "shot_body_part", "shot_type", "play_pattern"]].copy()

base["bajo_presion"] = tiros["under_pressure"].astype(int)

base["de_primeras"] = tiros["shot_first_time"].fillna(False).astype(int)

 

X = pd.get_dummies(base, columns=["shot_body_part", "shot_type", "play_pattern"],

drop_first=True)

y = tiros["gol"]

get_dummies

Convierte cada categoría en una columna de 0 y 1.

Los modelos necesitan números. Parte del cuerpo, tipo de tiro y jugada son texto; get_dummies crea una columna por categoría. drop_first evita una columna redundante.

6.2 · Entrenar y evaluar

Entrenamiento y test

python

X_train, X_test, y_train, y_test = train_test_split(

print(f"Entrenamiento: {len(X_train)} tiros ({y_train.sum()} goles)")

stratify

Mantiene la proporción de goles en entrenamiento y en test.

random_state

Fija el azar para que todos obtengan el mismo reparto.

Nunca evaluar con los mismos datos que se usaron para entrenar. stratify=y es importante aquí porque hay pocos goles. Más adelante se cambia el random_state para ver cuánto varía el resultado.

Regresión logística

python

lr = make_pipeline(StandardScaler(),

LogisticRegression(max_iter=1000, class_weight="balanced"))

prob_lr = lr.predict_proba(X_test)[:, 1]

balanced

AUC

6.2 · Evaluación

Matriz de confusión y umbral

Falsos positivos

Dijo «gol» y no lo fue. Con umbral 0,5 son muchos.

Falsos negativos

Dijo «no gol» y lo fue: una ocasión que se escapó.

El umbral decide

¿Preferimos no dejar escapar ninguna buena ocasión o evitar falsas alarmas?

Con el umbral 0,5 el modelo da muchos falsos positivos: lo cambiamos según el coste de cada error.

Big Data e IA · Bloque 6 · Machine Learning aplicado

11

La precisión de «Gol» es baja y es normal: la mayoría de los tiros no acaban en gol. El umbral es una decisión de negocio, no técnica. En el ejercicio se prueba con 0,3 y 0,7.

6.3 · Fiabilidad

Validación cruzada

Idea

Repetir entrenamiento y test 5 veces con repartos distintos.

Qué vemos

El AUC cambia bastante de una vuelta a otra.

Conclusión

Con unos cien goles, desconfía de un único número.

Mira la desviación, no solo la media.

Big Data e IA · Bloque 6 · Machine Learning aplicado

13

Con pocos goles el resultado depende de qué tiros caen en test, por eso el AUC puede variar al cambiar la semilla. Es una buena ocasión para hablar de incertidumbre al presentar resultados. Código: cross_val_score(rf, X, y, cv=StratifiedKFold(5)).

Cierre

Lo que nos llevamos

  • Un proyecto de ML empieza por la pregunta y los datos, no por el algoritmo.
  • Las variables bien construidas (distancia y ángulo) valen más que un modelo complicado.
  • Con pocos datos, un único número no es fiable.
  • Comparar con una referencia profesional enseña cuánto nos falta.
